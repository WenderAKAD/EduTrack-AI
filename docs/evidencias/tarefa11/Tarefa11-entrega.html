1 Objetivo e conceitos-chave

O objetivo é criar a tabela academic_tasks — as tarefas acadêmicas do aluno (lições, provas e trabalhos) — diretamente por código, no backend do Xano, seguindo o processo de planejamento do OpenSpec.

ConceitoO que significa no projeto
Spec-Driven DevelopmentPrimeiro se escreve a especificação da mudança; só depois se escreve o código. A spec é a fonte de verdade.
Tabela (Xano)Estrutura de dados do backend. Equivalentes: subjects, user e agora academic_tasks.
XanoScriptLinguagem declarativa do Xano para descrever tabelas, APIs e funções em arquivos .xs.
RelationshipCampo que liga uma linha a outra tabela — aqui, subject_id liga cada tarefa à sua disciplina.

3 A tabela academic_tasks

Seis campos foram definidos — exatamente os pedidos, sem extras (REGRA Nº 1 do AGENTS.md):

CampoTipoRegra
idintChave primária, auto-gerada
titletextObrigatório, filters=trim
descriptiontextObrigatório
due_datedateObrigatório — dia de prazo (sem horário)
statustextObrigatório, filters=trim
subject_idint (relationship)Obrigatório → aponta para subjects

Index declarado: primary em id e btree em subject_id (a listagem de tarefas por disciplina é o acesso esperado).

Posse herdada. A tabela não duplica user_id: a posse vem de subjects.user_id. Uma tarefa só existe dentro de uma disciplina, e a disciplina já é escopada por usuário — evita duas fontes de verdade para o mesmo dado.

4 Código XanoScript e push

O arquivo tables/academic_tasks.xs:

table academic_tasks {
  auth = false

  description = "Tarefas academicas do EduTrack AI..."

  schema {
    int id
    text title filters=trim
    text description
    date due_date
    text status filters=trim
    int subject_id {
      table = "subjects"
    }
  }

  index = [
    {type: "primary", field: [{name: "id"}]}
    {type: "btree", field: [{name: "subject_id"}]}
  ]
}

Enviado ao Xano (workspace 148813, branch v1) — o push é feito pelo desenvolvedor, não pela IA (REGRA Nº 2):

xano workspace push --branch v1 --include "tables/academic_tasks.xs"

  Tables               +1 created
  --- Changes ---
  CREATE           table              academic_tasks

  Pushed 1 documents to workspace 148813

7 Observações técnicas

TemaDecisão
EscopoApenas os campos pedidos. Sem user_id (posse herdada), sem enum de status, sem timestamps e sem endpoint.
Datadue_date é date, não timestamp — evita inventar um horário.
guidNão declarado no arquivo: o Xano gera no push e devolve para o arquivo local.
Push isoladoEnviado com --include, porque o CLI ordena por caminho e academic_tasks viria antes de subjects.
Sem push pela IAREGRA Nº 2: a IA gera/valida os arquivos; o envio ao Xano é do desenvolvedor.
EnunciadoCita docs/*_guideline.md e a Paleta XanoScript, que não existem aqui; o fluxo real usa o Xano CLI.
